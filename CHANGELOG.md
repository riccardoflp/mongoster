# Changelog

## 0.7.0

- **Insert dialog**: `Insert` (in the toolbar, or `+` on a collection in the tree) opens a dialog in the collection's tab instead of an editor tab to save: type or paste the documents and press `Insert` (`Ctrl+Enter`). It takes one document, an array (inserted with `insertMany`), JSON Lines or a pasted `insertOne(…)` / `insertMany(…)`, in mongosh syntax or Extended JSON, with autocomplete and syntax colors, and says while you type how many documents it found or what's wrong. `Template` starts from the collection's fields; errors (a duplicate `_id`, validation) show in the dialog, and when one of several documents is refused it says how many went in. `Keep open` inserts several in a row; `Open in Editor` still opens an editor tab. `Duplicate` opens the dialog with the copy.
- **Copy as**: `Copy ▾` in the document dialog copies the document as mongosh, Extended JSON, plain JSON, YAML or an `insertOne` command. The same formats are in a new right-click menu on the rows, with `Open document`, `Copy value`, `Duplicate…` and `Delete document`.
- **Select several rows**: Ctrl/Cmd+click, Shift+click and Ctrl+A select documents in the table (highlighted, with `N selected · Clear` next to the paging); right-click a selected row to copy them as a mongosh or Extended JSON array, JSON Lines, JSON, YAML, an `insertMany` command or CSV of the visible columns, export them, open `Update many` on their `_id`s, or delete them (also the `Delete` key), with undo and redis-oplog.
- **Actions on a column**: the header's right-click menu has `Rename field…` (`$rename`, dotted paths too), `Remove field…` (`$unset`, also from the elements of an expanded array) and `Convert type…` (`$convert` to string, int, long, double, decimal, bool, date or objectId, keeping the values it can't convert and saying how many), on the documents matching the filter, with the count in the confirmation, undo and redis-oplog; a renamed column keeps its place, width and visibility.
- **Generate test documents**: `Generate Test Documents…` on a collection or view, or `Generate…` in the `Schema` tab, creates up to 1,000,000 fake documents that look like the collection's: each field appears as often as it was seen, with the same mix of BSON types and the frequent values re-used; numbers and dates follow the histogram; strings follow the field name and the values seen (emails, URLs, UUIDs, phones, names, codes). They go into this collection or another one on any connection, after a preview of 3 documents, with an optional seed for reproducible output; inserts run in batches with `Cancel` and can be undone like an import.
- **Atlas Search and Vector Search indexes**: the `Indexes` tab lists the collection's search indexes below the others, with type, colored status (`READY`, `BUILDING`, `FAILED`, …), whether they're queryable, and the definition in short; clicking one shows the full definition, the mongosh command and the status on each host, and the list follows a build every 5 seconds while the tab is shown. `Create search index…` takes the name, the type and the definition as text with colors and suggestions, filled in by `Dynamic mapping`, `Static mappings` from the documents' fields, or for vectors the path, dimensions (from the sampled arrays), similarity, quantization and filter fields; `Edit…` and `Drop` change and drop them. A server without search says what it needs (Atlas, an Atlas local deployment, or Community 8.3+ with `mongot`) instead of failing. In the pipeline editor, `$search`, `$searchMeta` and `$vectorSearch` have templates and suggestions (the collection's search index names in `index`, and `$meta` scores in `$project` / `$addFields`), and are marked when they aren't the first stage.
- **Sharding in the server monitor**: on a mongos, the new `Sharding` section shows the shards (replica set, state, draining, zones, chunks, data and documents), the sharded collections (shard key, balancing, chunks and data per shard with a distribution bar, balance, jumbo chunks; click for zone ranges and the `config.collections` document), the balancer and the migrations of the last 24 hours, and the recent migrations, splits and balancer rounds with failures highlighted; `Stop Balancer…` / `Start Balancer…` and `Disable Balancing…` / `Enable Balancing…` for a collection after a confirmation, not on read-only connections. On a standalone server or a replica set it says it isn't a sharded cluster, and without the `clusterMonitor` role it shows what it can read.
- **Explain on a sharded cluster** shows each shard's plan with its numbers, so a collection scan or the index used on a shard is reported.
- **Sessions and transactions in the playground**: `db.getMongo().startSession()` gives mongosh's sessions: the collections of `session.getDatabase("…")` run every operation in the session, and `startTransaction()` / `commitTransaction()` / `abortTransaction()` / `withTransaction(() => { … })` work as in mongosh, with the driver's retries on write conflicts and no `await` needed in the callback. With redis-oplog, a transaction's writes are published in order only once it commits, never if it aborts. Sessions left open at the end, after an error or a `Cancel` are ended with their transaction aborted, and the output says so. On a standalone server the error explains that a replica set is needed (a single-node one is enough). Autocomplete knows `db.getMongo().`, sessions and `session.getDatabase("x").`.
- **No `await` needed inside expressions in the playground**: every call is awaited where it is, so `db.orders.find().toArray().length`, `db.stock.findOne({}).n`, `print(db.users.countDocuments())` and template literals give their values instead of `undefined` or a Promise, also in the blocks of `if`, `for`, `while` and `try` at the top of the script and in `async` functions; cursors stay lazy until they are read. Before, such a call kept running unawaited, and inside a session it could fail after the session ended.
- **Importing and exporting connections**: `Import Connections…` (the view's `…` menu, the Command Palette or a folder) reads MongoDB Compass's export (also encrypted with a passphrase), Mongoster's own or a list of connection strings (`name = mongodb://…`), from a file or the clipboard, with name, color, TLS files and SSH tunnel; it shows which connections already exist (`Skip`, `Replace` or `Keep Both`) and lets you choose the folder. `Export Connections…` writes the chosen connections as Mongoster JSON (folders, colors, read-only, TLS, SSH, redis-oplog), Compass JSON or a list, without passwords, with them in clear text, or encrypted with a passphrase the way Compass does it.
- **Automated tests**: `npm test` runs unit tests of the query syntax, pipelines, query builder, CSV, schema, explain, profiler, code generation, archive format and the other shared modules, and `npm run test:integration` runs the playground and a backup/restore round trip against a real mongod; the Build workflow runs both. A regex pattern containing `//` (such as `http://x`) is now written as a `/…/` literal that can be read back.

## 0.6.0

- **redis-oplog**: a connection can publish the writes made in Mongoster to Redis as the Meteor package `cultofcoders:redis-oplog` does, so that the publications of the Meteor apps using it update as for their own writes. The `redis-oplog` section of `Connection Settings (TLS / SSH)…` takes the Redis URL (`redis://` or `rediss://`, kept in SecretStorage), the app's channel prefix (`globalRedisPrefix`), its namespaces and the databases and collections to publish (`app`, `app.users`, `app.*`, `*.logs`; empty, all of them); `Test Connection` checks Redis too. Inline edits, `Edit` / `Insert` / `Delete` of documents, `Update many` / `Delete many`, undo and the playground's writes (`insertOne` to `bulkWrite`, `findOneAnd…` included) are announced document by document, with the fields they changed. A Redis error doesn't stop the write: a warning says the change couldn't be published.

## 0.5.0

- **Filter for databases and collections**: `Filter Databases and Collections…` (the filter icon in the tree's title) shows only the databases and collections whose name contains the text, ignoring case, while it's typed; database and collection can be written together, so `shop.ord` finds `shop.orders`. The databases that match, or that have a collection that matches, open by themselves under the connected connections; `Filter: …` above the tree says what's filtered, and `Clear Filter` (the filled icon) shows everything again.

## 0.4.0

- **Backups as a single `.agz` archive**: `Back Up…` can write an archive in `mongodump --archive --gzip`'s format (`Archive (.agz)`), which `mongorestore --gzip --archive` restores, besides the folder formats.
- `Restore from Backup…` restores archives written by Mongoster or by `mongodump --archive` (`.agz` or uncompressed `.archive`, also with collections alternating), with each collection's checksum checked. It now asks first whether the backup is an archive or a folder: before, the dialog only accepted folders, so an archive file couldn't be chosen. On a collection, an archive can be chosen too, then one of its collections.
- A column header can be dragged onto Sort (`▲ ascending`, `▼ descending`) and Project (`include`, `exclude`), not only onto the filter; a field already there can be dropped on `✕ remove`. Sorting by several fields no longer needs typing.
- **Syntax colors in the query inputs**: the filter, Sort, Project, the stages, the pipeline as text, Update many and the index options color field names, operators, strings, numbers, `ObjectId(…)`, dates, regexes and comments with the syntax colors of the active color theme, as the table does. Field paths in a stage (`"$amount"`) take the color of field names.
- A stage of the pipeline widens to its longest line, up to 640 px, instead of wrapping it at 280 px: a value like `ObjectId("…")` is no longer cut in two.
- The panels follow the color theme more closely: selected tabs (Find / Aggregate / …, the monitor's tabs) and toggles that are on (Builder, the pipeline's view) take the colors of VS Code's toggles instead of the primary button's, checkboxes, radio buttons and dropdowns are drawn with the theme's colors instead of the system's blue, and buttons and inputs have VS Code's rounded corners and secondary button border.

## 0.3.0

- **Desktop app**: Mongoster also runs without VS Code, as an app for Windows, macOS and Linux with the same features: the connections tree with its menus, tabs on two sides, the editor of VS Code for documents and playgrounds, the Command Palette, a settings tab, dark and light themes, and the MCP server. `npm run app` starts it from the sources and `npm run package:app` builds the installer; a GitHub Actions workflow builds the installers for the three systems and the extension's package.
- **Indexes tab**: `Create index…` opens a dialog with the fields (suggested from the documents, with direction or type), the name and the options (`Unique`, `Sparse`, `Hidden`, `TTL`, `Partial`, `Collation`, text weights and language, any other option), or the keys and options as text; the mongosh command is shown while editing. It replaces the `Keys` / `Options` line.
- `Edit…` changes an existing index: hiding it and its TTL in place, anything else by dropping and building it again after a confirmation — the new one first when the two can exist side by side, and the old one is kept or restored if the new definition is refused. `Duplicate…` starts a new index from an existing one.
- Clicking an index shows its full definition, the command that creates it and the uses on each member of a sharded cluster. The list shows the size of each index compared with the largest, the uses per day, the totals, and can be sorted by name, size and usage.
- An index being built is listed as `building` with its progress; the dialog can be closed while the build goes on.
- An option of `createIndex` that MongoDB doesn't know (e.g. a typo) is now refused instead of being silently ignored.
- Wildcard indexes: a wildcard written wrong (`address.*` or `**` instead of `address.$**` or `$**`, which MongoDB would quietly take as a field with that very name) and what a wildcard index can't have (`unique`, `sparse`, TTL, a type, a `wildcardProjection` missing or out of place) are pointed out in the dialog before saving. An existing index on such a field is marked `not a wildcard` in the list.
- `Indexes` in the context menu of a collection opens its tab on the indexes.
- MCP server with several VS Code windows open: the tabs the AI opens appear in the window you used last, instead of the first one opened. The port follows the focus, and is taken over within a few seconds when the window that had it is closed.
- `Mongoster: Change MCP Server Port…`, also in the setup command. When another program is using the port, a warning says so and `Change Port` suggests a free one, instead of only a line in the log.
- A new access token generated in one window now applies to the others right away.
- Disconnecting a connection that is expanded in the tree no longer reconnects it at once: it collapses and stays disconnected until it is expanded again.

## 0.2.0

- **MCP server for AI assistants**: GitHub Copilot, Claude Code, Cursor and other MCP clients can list the connections, databases and collections, describe a collection's fields and indexes, run read-only queries and aggregations, and open a query, an aggregation or a global search in Mongoster's tabs. `Mongoster: Set Up MCP Server for AI Assistants…` turns it on and copies the configuration. It listens on `127.0.0.1` with an access token, never writes, and `mongoster.mcp.readDocuments` can keep documents from the AI.

## 0.1.1

- Values in the table, the playground results, the server monitor, the global search and the index advisor take the syntax colors of the active color theme, and change with it.
- In a narrow tab, the filter keeps a usable width: its buttons, the top bar, Sort / Project, the pipeline buttons and the status bar wrap instead of squeezing it.
- Popups use the theme's shadow.
- Empty arrays and objects in the JSON view of a document or of explain are no longer centered on their own line.
- In the Indexes tab, the empty actions cell of the `_id_` index takes the height of its row.
- The README and the changelog are now in English.

## 0.1.0

First release.

- **Connections**: connection string or a form with TLS and SSH tunnel, connection strings and passwords in VS Code's SecretStorage, read-only connections and colors to tell them apart.
- **Browsing**: tree of connections, databases, collections and views; creating, renaming and dropping databases and collections.
- **Table**: nested columns and arrays of objects, sorting, columns that can be hidden, reordered, resized and pinned; inline editing of cells.
- **Queries**: filter, sort and projection in mongosh syntax with autocomplete, visual query builder, drag & drop of cells into the filter, history and saved queries.
- **Aggregate**: stage-based pipeline editor with a preview of each stage and saving as a view.
- **Documents**: opening and editing as JSON, insert, duplicate, delete, update many / delete many, undoing changes.
- **Data**: export (JSON, JSON Lines, CSV), import, copying collections, backup and restore in the mongodump format, comparing two collections.
- **Analysis**: schema, charts, global search in any field, relationship diagram, explain.
- **Indexes**: create, hide/unhide and drop; suggestions for indexes to create, redundant and unused ones.
- **Tools**: mongosh playground, code generation, server monitor (operations, profiler, stats, replica set), GridFS, users and roles, change streams.
